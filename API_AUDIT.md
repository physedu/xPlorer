## dev.17 — native-first audit

The package's native field assignment path already calls ComponentValue for rank zero and AllComponentValues for positive rank; ChangeComponents handles variance. The official xCoba 1.3.0 source uses ComponentValue internally in array assignment, metric installation and component derivation. Thus global interception of these functions would conflate inputs and derived values. New owned-object UpValues add disjoint shorthand and explicit Managed -> True for overlapping scalar/deletion operations. No global downvalues modified. Ricci/Riemann/Einstein/Weyl and other geometry getters are native xTensor operations; ToBasisOf/ToValuesOf and ConnectionDifference are candidates for removal after migration. Keep PortExpression, ToComponents, CreateBackground, reconstruction and lifecycle, and background-local xPert handling. DefChart, DefBasis, SetBasisChange, CTensor, ChangeComponents, ToValues, VarD and VarL remain native. No automatic capture of external chart/basis or individual component operations; these need a separate contract.

### Follow-up native audit — HeldComponentValue (open, no version bump)

Real Mathematica 15.0.1/xAct 1.3.0 probe against published dev.25 83b7e6725ea816a536c1897e4f6b305c0d257a1f: see Tests/29_HeldComponentProbe.wl and Tests/dev25-held-probe.json. Native ComponentValue rule, list of rules and paired component/value list forms already dispatch to managed input hooks; the recorded coordinate tuples are {0}->4, {1}->2, {2}->3, {3}->5. Do not duplicate those dispatch paths.

HeldComponentValue with a literal owned head and chart (injected by With to preserve HoldFirst) sets the native covariant component to 7, but leaves its managed record at 4. ToValues gives the raised value -7, while a preceding HeldComponentValue raised query returns an identity rule. A held scalar assignment sets the native scalar to 9 without creating its managed record. ClearComputedValues replays the old vector value 4 and leaves the unregistered scalar at 9 in this experiment; scalar reconstruction was not tested. This is a confirmed synchronization defect, not a passing regression group.

Native xCoba HeldComponentValue has HoldFirst and calls ICV without the CVSimplify step used by ComponentValue. A correction must preserve evaluation and simplification semantics, native return rules, set-state behavior and exact replay; do not indiscriminately replace held calls with evaluating ComponentValue or add global capture. RuleToSet/SetToRule, WithSetValues and partial DeleteTensorValues remain open. No speculative package edit, release, installer change or new version is made in this audit checkpoint.

## dev.27 — native field removal audit

A native DeleteTensorValues call identifying the exact registered primary-chart authoritative field group, in Rule state, removes that input record and invalidates its dependent values; a ValID delegates through the native dispatch. Derived-only group deletion remains native and leaves the input record/revision intact. Existing replay conservatively rebuilds the affected field head and recorded dependents, including surviving LI orders, rather than promising to preserve every native cache on that head. ComponentValue[component,Null] and supported literal HeldComponentValue removal now downgrade a complete field input to a sparse record of remaining independent components; an unknown component remains symbolic, not zero. Removing the last sparse value removes the record. The existing stage/replay path still rejects unsupported self-referential incomplete edits. Sparse tuples must be expressed in their record's declared variance: if native ToCanonical interchanges opposite-variance slots, retain a representative in the declared input variance with its correctly signed value; mixed-variance edits deduplicate by native canonical identity. No custom permutation engine or new public command. Earlier affected mixed-variance sparse records may have stored incorrect tuples; no automatic recovery of original input is possible from those records, so reassign the affected field inputs from the original expressions. Native Set-state transitions, held metric/geometry, derivative/secondary-chart input deletion, and general native chart/basis and independent connection lifecycle remain open.
Native single-bases-list deletion may be ambiguous when several native groups exist; keep the native resolution and recommend exact nested bases lists or ValID. Existing full field deletion and old managed setters remain. Set-state synchronization and external derivative/secondary-chart source semantics remain separate open issues.
